# learnCode

## 基础要求

目的：

把一份**代码**（一个仓库、一个模块、一条链路）**提炼**成"代码知识卡"，帮助真正读懂一套代码，而不是逐文件流水账。

本命令承袭 `learn` 的范式——**提炼精华，不是扩写**：对每一个"承重知识点"，只留一句 ≤20 字的锚点（读代码时能反复默念、提醒自己"这块只干什么/别碰什么"）+ 一个最贴切的类比 + 它的陷阱与隐式契约 + 怎么用/怎么改（接你的知识图谱）。理论依据同样是《如何高效学习》的比喻法与费曼技巧。

但代码和书有四点本质不同，决定了流程比 `learn` 多几步：

1. **代码是图不是线**——不能从头读到尾，必须先"侦察建图"再读。
2. **代码能跑**——理解可以被"运行/加一行 log/跟一条请求"验证（书没有的杀手锏）。
3. **承重 vs 管道**——一个仓库大部分是胶水与样板，真正承重的抽象/数据结构/不变量只占一小撮；**只学承重**。这是 `learn` 的"论点 vs 示例"在代码里的对应，也是本命令的命门。
4. **隐式契约**——代码里最坑的是"没写出来的约定"（调用顺序、幂等假设、谁负责校验、某字段不能为空）。书里没有这一层。

命令格式：

- `learnCode [代码路径] [可选：范围/目的]`

示例：

- `learnCode /path/to/repo`（不给要求 → 默认鸟瞰整库架构）
- `learnCode /path/to/repo src/auth`（吃透 auth 模块）
- `learnCode /path/to/repo 我要给它加一个限流中间件`（目的=改，重心落到"改哪、别踩哪"）

适用场景（**本命令主要面向完全陌生的项目**）：

- 上手一个**完全陌生**的代码库（第三方库、新工作接手的系统），要改它/调它的 API/评估它/理解架构——重心在"入口在哪、怎么跑起来、对外契约、要改哪、别踩哪"。
- （次要）回坑自己写过的旧项目（roleflow / AegisFlow 等），捡回"当时为什么这么写"。

输入：

- 一个代码路径（仓库 / 目录 / 单文件）。可选的范围与目的（自然语言即可）。

输入要求：

- 必须提供代码路径。
- **不给目的/范围时，默认按"鸟瞰（架构地图）"做，目的按"理解架构"。**
- 若代码不在本机、需要克隆或有环境依赖，必须先提示用户。

输出结果：

- 输出目录固定为：`aiagentWiki/learnCode/`
- 小目标（单模块 / 单链路）：单文件 `aiagentWiki/learnCode/[yyyyMM]-[仓库名或模块名].md`
- 大目标（整库鸟瞰 / 多模块）：文件夹 `aiagentWiki/learnCode/[yyyyMM]-[仓库名]/`，内含 `00-架构总览.md` + 各模块/各主链路一份卡片文档。
- 更新 `aiagentWiki/learnCode/index.md`（格式参照 `learn` 的 index：链接行 + `Code Path` + 100 字以内简短摘要）。

## 两条核心原则

1. **承重优先，管道跳过**：先把代码分成**承重代码**（核心抽象、关键数据结构、主控制流/数据流、不变量、非显然的设计决策）和**管道/样板**（胶水、显然的 CRUD、配置、生成代码）。只有承重才成"知识点卡"；管道只标位置、不"学"。这是治"逐文件流水账/信息过载"的根本手段。
2. **接个人知识图谱优先**：每个承重点尽量命中你已内化的软件设计/AI 系统 L3 模型；命不中就诚实标注，登记为"待入图"（见下）。

## 执行流程（六阶段）

**Phase 0 · 定范围与目的（询问）**
- 范围：整库鸟瞰 / 一条主链路 / 一个模块。目的：改（加功能/修 bug）/ 用（调 API）/ 评估（审设计与坏味）/ 理解（学架构）。
- **不给 → 默认：范围=整库鸟瞰，目的=理解架构。** 目的决定重心：改→重仓"陷阱/怎么改"；评估→重仓"设计决策/坏味"；用→重仓"对外契约/入口"。

**Phase 1 · 侦察建图（先别逐行读）**
- 摸清：语言/框架/构建方式、目录结构、**入口点**（main/router/index/CLI）、**核心数据模型/类型**、依赖关系、**怎么 build / run / test**。
- 先读 README / 配置 / 测试——最便宜的定向。
- 产出一张"代码地图"：模块 → 职责 → 依赖（mermaid）。这相当于 `learn` 的"先划分知识点"。

**Phase 2 · 划承重 vs 管道（命门）**
- 通读（大库可抽样）后，列出**承重清单**：哪些是承重知识点、哪些是管道（只标位置）。
- 判据：**承重**＝核心抽象/关键数据结构/主控制流数据流/不变量/非显然设计决策；**管道**＝胶水/显然 CRUD/配置/生成代码/框架样板。
- 宁少勿滥：抓不住一句锚点的，通常不是独立承重点，合并或降级为管道。**这一步做不好，就会退回"逐文件流水账"。**

**Phase 3 · 跟主链路（trace the spine）**
- 挑 1–2 条最有代表性的端到端路径，**跨文件跟一遍**：一次请求的生命周期 / 一个关键功能的数据流 / 启动时序。活的执行路径比静态读文件更能教会架构。

**Phase 4 · 出卡片（提炼）**
- 先写"承重知识点总览"表，再逐个承重点写卡（结构见下）。**每张卡带定位指针**，能点回真实代码（相当于 `learn` 的 Source Path）。定位约定：**以 `文件:符号名`（函数/类型/方法）为主**；只有在描述某一段具体逻辑时才用 `文件:行号`——符号名抗代码漂移，行号会随改动失效。

**Phase 5 · 跑一遍验证（可选但强烈建议；这是 `learn` 没有的）**
- 用 run / trace / 读测试 / dry-run 确认心智模型没错；给一句"怎么验证我真懂了"（改 X 会导致 Y，跑跑看）。呼应 `verify` 精神。
- 若 repo 跑起来成本高，可降级为"静态 trace + 列出验证步骤"，但必须在文档里**显式说明未实跑**。
- 默认**不改动目标代码**；若必须加 log 才能验证，须先征得用户同意、用可回退方式（临时改动/临时分支），并在文档说明。

## 文档结构（固定）

元信息头（第一个 `## ` 之前）：
- `Code Path: <被学习代码的路径>`（大库可再标 `Commit: <hash/分支>`）
- `语言/框架：…`
- `范围：整库鸟瞰 / 模块<名> / 链路<名>`
- `目的：理解架构（默认）/ 改 / 用 / 评估`
- `如何运行：<build/run/test 命令>`（拿不到标"未知，本次静态分析"）
- `知识地图: 已读取 / 未找到`
- `Confidence: …`

### 一、架构地图（鸟瞰一眼扫）
- 一段话主旨（这套代码到底在干嘛、怎么组织的）。
- mermaid：模块→职责→依赖，或主链路的数据流。
- 入口点清单 + 核心数据模型/类型（最快理解一套代码的钥匙）。

### 二、承重知识点总览表
| 承重点 | 锚点（≤20 字） | 位置（文件:符号名） | 对应模型 |
|---|---|---|---|
- 锚点是每张卡最重要的产物：一句 ≤20 字、punchy、可默念，说清"这块只干什么/别碰什么/数据怎么流"。

### 三、承重知识点卡片
每个承重点一张卡，顺序与总览一致，固定块（严格照此）：

```
### KP<n> <承重点名>（如：写路径唯一入口 CommandBus）
> 锚点：<那句 ≤20 字的话>
📍 <文件:符号名>（函数/类型/方法为主；描述某段具体逻辑时才用 文件:行号；多处则列关键几处）

**是什么/干什么**：<忠实说清它的职责与主流程；承重处可贴一小段关键代码或点到 文件:符号名（具体逻辑处才加行号），管道只标位置、不贴>。

**费曼·换个领域**：<用一个熟悉领域把它讲出来——架构尤其吃这一招>。〔仅当类比容易被误用时补一句 ⚠边界：…〕

**陷阱/隐式契约**：<代码里非显然的约定/不变量：必须先 A 再 B / 这里假设幂等 / 失败不回滚 / 谁负责校验 / 某字段不能为空>。← 代码专属，务必真实、不编造。

**如何用/如何改（接知识图谱）**：<命中你哪个 L3 模型（模块名+锚例）；要加功能/改动该动哪、别踩哪；一句可验证的预测。以说清为准，不设硬长度限制，但别冗长>。
```

### 文末：代码疑问与坏味 · 待入图
- `## 代码疑问与坏味`：你没看懂的、像 bug 的、耦合过重/缺测试/命名误导的，逐条登记（供后续 `verify` 或提 issue）。无则省略。
- `## 待入图（知识地图空白）`：命不中你知识地图的架构模型，逐条登记为将来"编程/架构知识地图"的候选（对应 `learn` 的地图空白）。无则省略。

> 不写：逐文件流水账、大段贴码、解释显然的管道、把每个函数/文件都列一张卡。

## 大仓库处理（分模块/链路，subagent）

类比 `learn` 的长材料流程：

1. 主 AI 先完成 Phase 1（侦察建图）+ Phase 2（划承重）+ Phase 3（定主链路），向用户复述处理计划（哪些模块/链路成文档、各交给哪个 subagent）。
2. 再把各模块 / 各主链路分给 subagent，每个只处理自己那块、产出该块的卡片文档，**不得跨块**。
3. 主 AI 回收复核：是否把管道误当承重、锚点是否 ≤20 字、定位指针（文件:符号/行号）是否真实存在、陷阱/契约是否真实、有无臆测未读代码、有无编造。
4. 主 AI 亲写 `00-架构总览.md`：全库**承重锚点墙**（各模块锚点汇总）+ 架构图 + 主链路 + 跨模块地图命中矩阵 + 疑问坏味汇总 + 待入图汇总。不写全库测试/学习顺序。
5. 若"必须用 subagent"与运行环境上层约束冲突，先显式说明冲突点并询问用户。

## 询问规则

1. 编译开始前，最多问 2 个（选择题）：
   - **目的**：A. 理解架构（默认）B. 改（加功能/修 bug）C. 用（调 API）D. 评估（审设计/坏味）。
   - **范围**（仅当路径是整个大库时问）：整库鸟瞰（默认）/ 指定模块 / 指定一条主链路。
   - 需要 Phase 5 验证而不知如何运行时，可追问一句"怎么 build/run/test"；拿不到就降级为静态分析并在文档标注。
2. 用户未回复/拒绝/无法提供 → 一律按默认（鸟瞰 + 理解架构 + 静态）执行，不反复追问。

## 硬性约束

- 只允许写入 `aiagentWiki/learnCode/` 下的文件；**不得改动被学习的目标代码**。唯一例外是 Phase 5 为验证而加临时 log/dry-run：须先征得用户同意、用可回退方式、并在文档说明，事后还原。
- **承重优先**：先分承重/管道，管道只标位置、不成卡；禁逐文件流水账、禁大段贴码、禁把每个函数都列成卡。这是第一约束。
- **每个承重点必须有 ≤20 字锚点 + 定位指针（`文件:符号名`为主，描述具体逻辑处才用 `文件:行号`）**；憋不出锚点的合并或降级为管道。
- 每卡只给**一个**最贴切类比；仅当类比会误导才补一句 `⚠边界`。
- **"陷阱/隐式契约"必须是代码里真实存在的约定/不变量**，禁编造；拿不准标 `Confidence: Low`。
- **"如何用/如何改"必须接知识图谱**：命中 L3 模型写模块名+锚例，命不中标 `无对应模型` 并登记"待入图"，不得写成空泛口号。
- 一切事实（职责、数据流、契约、定位指针）必须与真实代码一致，禁捏造文件/符号/行号、禁臆测未读代码的行为（未读就标"未核"）。
- 文档结构固定为"架构地图 + 承重总览 + 承重卡片（+ 疑问坏味 + 待入图）"；不写五阶段材料、记忆术、测试题。
- 主语言必须是简体中文；不确定的内容标 `Confidence: Low`。
- 大仓库必须分模块/链路交给 subagent，主 AI 必须复核回收结果。
- 如果本规范与运行环境上层约束冲突，必须显式说明冲突点并询问用户如何处理。
