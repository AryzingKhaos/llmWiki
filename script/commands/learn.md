# learn

## 基础要求

目的：

把一份需要深入理解的资料（一本书、一篇论文、一篇文章、一部视频、一段音频），**提炼**成一套"知识点卡片"式的高效学习文档。

本命令的范式是**提炼精华，不是扩写**。学习的目的是把厚书读薄：对每一个知识点，只留下**一句 ≤20 字的锚点**（实践时能反复默念、提醒自己"目标是什么、该做成什么样"）+ **一个最贴切的类比**。凡是不能被一句锚点抓住的扩写，都不要写。理论依据是斯科特·扬《如何高效学习》的**比喻法（在陌生知识与熟悉经验间架桥）**与**费曼技巧**，以及学习者本人知识地图记录的原理：`知识即联结网络（相邻领域共通处免学）`、`模型=可类比的内在逻辑`。

两条贯穿始终的核心原则：

1. **先划分知识点，区分"论点"与"示例"**（见"前置：知识点划分"）。只有作者的论点／知识点才值得"学"；研究过程、实验、案例、人名、数字都只是**示例**，仅作数据引用，不单独成为学习对象、不逐一展开。这是治"信息过载"的根本手段。
2. **个人知识地图优先**：每个知识点尽量命中学习者已内化的 L3 模型；"如何应用"一节必须深度接到知识地图上（见"个人知识地图优先"）。命不中就诚实标注，并登记为知识地图的空白/前沿。

命令格式：

- `learn [输入路径]`

示例：

- `learn improveWiki/raw/深度工作.pdf`
- `learn investWiki/raw/2026/某论文.pdf`
- `learn aiagentWiki/raw/某视频.mp4`

适用场景：

- 还没读过原文，想直接靠一份"薄"文档快速抓住一本书/一篇文章的**核心论点 + 锚点**
- 想把一份资料提炼成可在实践中反复调用的"锚点 + 类比 + 应用"卡片，而非存档摘要（存档/摘要请用 `ingest`）
- 材料是视频或音频，需要先转成文字再学习

输入：

- 一个文件路径（**唯一必填项**）。可以是文本类（md/txt/pdf/epub/html 等），也可以是视频/音频（mp4/mov/mp3/m4a/wav 等）。

输入要求：

- **`libraryName` 从路径自行推断**：取路径中第一个形如 `xxxWiki/` 的目录段作为 `libraryName`。若无法推断，必须提示用户指定归入哪个 library，不能擅自决定。
- 若输入文件不在对应 library 的 `raw/` 目录下，必须先明确警告用户，再继续流程。
- **视频/音频输入**：必须先用 `video2text` skill 将其转写为文字稿（B 站链接可用 `bili-video-to-text` skill），以转写稿作为实际输入语料；转写稿路径记录在文档元信息中。
- 开始编译前，按"询问规则"与用户确认（长材料确认重点章）；用户未回复/拒绝/无法提供时，按默认值执行。

输出结果：

- 输出目录固定为：`[libraryName]/learning/`
- 短材料（单篇文章、论文）：单个文件 `[libraryName]/learning/[yyyyMM]-[中文名].md`
- 长材料（整本书、多章节课程）：新建文件夹 `[libraryName]/learning/[yyyyMM]-[中文名]/`，内含：
  - `00-总览.md`（全书锚点墙 + 结构图 + 跨章模型命中矩阵 + 地图空白汇总 + 各章目录）
  - `01-[章节名].md`、`02-[章节名].md` …（每章一份卡片式文档）
- 更新 `[libraryName]/learning/index.md`（格式参照 `wiki/index.md` 条目格式：链接行 + `Source Path` + 100 字以内简短摘要）

## 前置：知识点划分（本命令的第一步，最重要）

在写任何卡片之前，必须先通读语料，把它拆成**知识点清单**。判据是区分两类内容：

- **论点／知识点**（要"学"的）：作者主张的、可迁移的道理、原理、方法、模型。例："人们更关注负面的信息"是一个论点。
- **示例／研究过程／数据**（不"学"、只引用的）：为支撑论点而给出的实验、案例、人名、统计数字、故事。例："负面 vs 正面心理研究论文数量约 21:1"是示例；它只作为该论点下的一行数据引用，**不单独成为一个知识点、不展开讲**。

规则：

1. 一个知识点 = 一张卡。示例不单独成为知识点：**能点明论点的重点示例并入该卡的"原文解释"**（保持原意），次要示例/数据用"例｜"一行引用；无论哪种，都不把案例/研究过程铺陈成段。
2. **宁少勿滥**：只提炼真正的论点。一章即使内容很多，知识点也应收敛到少数真正核心的条目；把并列的小论点合并、把纯背景/铺垫剔除。判断标准是"这条能不能被一句锚点抓住"——抓不住的，往往不是独立知识点。
3. 人名、机构、年份、精确数字一律当数据，不进锚点、不进模型列，只在"例｜"里出现（且只在确有必要时）。
4. 划分完成后，才进入"卡片模板"逐点填写。

## 个人知识地图优先

学习者维护一份个人知识地图（`/Users/aaron/workspace/个人/天赋/知识地图.md`），记录已内化的 L3 思维模块及其"锚例"。编译开始前必须完整读取，建立"可用模型清单"。它在两处发力：

- **"对应模型"列**（锚点总览表）：每个知识点尽量标注它命中的地图 L3 模块（写模块名）。
- **"如何应用"节**（每张卡）：把知识点接到地图上——命中哪个模型、复用哪个锚例、据此变成学习者能执行的一个动作。

架桥三档（从高到低）：

1. **命中已有模型**：知识点对应地图里某 L3 模块 → 标出模块名 + 复用的锚例。
2. **命中萌芽区**：只能对应"萌芽区"模型 → 照用，注明"此处迁移可作它转正的新锚例候选"。
3. **无对应模型**：地图里确实没有 → "对应模型"列标 `无对应模型`，并在文末"地图空白提示"登记（这是学习者知识版图的空白/前沿信号，供后续 `frontier`/`concept` 参考）。

铁律：宁可标"无对应模型"，也不牵强套用。若文件缺失，在元信息标注 `知识地图: 未找到（回退通用类比）` 并继续。

## 卡片模板（每份文档的固定结构）

每份学习文档（短材料的单文件，或长材料的每章文件）结构**固定为两节**，不得增删、不得改变顺序：

文档头部（第一个 `## ` 之前）放元信息 bullet 区：
- `Source Path: <相对仓库根目录的路径>`（源文件不在 `raw/` 下时另加 `Warning: source file is outside [libraryName]/raw/`）
- `对应原文：<书名/章节名>`
- `学习目的：实践应用（B）`（或用户指定）
- `知识地图: 已读取 / 未找到（回退通用类比）`
- （视频/音频）`转写稿：<路径>`
- `Confidence: …`

### 一、锚点总览（全章一眼扫）

一张表，列出本章所有知识点。这是"锚点墙"，供学习者一眼扫完、在实践中快速调用。

| 知识点 | 锚点（≤20 字） | 对应模型／概念 |
|---|---|---|
| 知识点名 | 一句祈使/提醒句 | 命中的地图 L3 模块名（或概念名 / 无对应模型） |

- **锚点是每张卡最重要的产物**：一句 ≤20 字的话，说清"目标是什么、该做成什么样"，是学习者实践时反复默念的那句。硬指标 ≤20 字（极个别确实压不下才允许到 ~25 字）。锚点要**punchy、可记、有画面或有动作**，不是复述定义。
- "对应模型／概念"列优先填地图命中的 L3 模块名（见"个人知识地图优先"）。

### 二、知识点卡片

每个知识点一张卡，顺序与总览表一致。每张卡固定四行块（严格按此，不加别的）：

```
### KP<n> <知识点名>
> 锚点：<那句 ≤20 字的话>

**原文解释**：<用简洁但完整的话讲清这个论点原文在说什么。可以稍长一点：把原文用来点明/支撑这个论点的**重点示例或重点说明**融进来（保持原意、不改变含义），让人读完就懂"这个论点在讲什么、凭什么"。但不铺陈与论点无关的枝节>。
例｜<可选：额外的次要示例/数据，一行引用即可；能点明论点的重点示例已并入上面的原文解释，不必在此重复>。

**费曼·换个领域**：<用另一个学习者熟悉的相邻领域，把这个知识点讲出来——一个最贴切的类比即可，讲到"哦原来如此">。〔仅当这个类比容易被误用时，补一句：⚠边界：在<X>处不成立。〕

**如何应用（接知识图谱）**：<命中地图哪个 L3 模块（写模块名+锚例）；据此把知识点变成学习者能马上做的具体动作/提醒。**以说清楚为准，不设硬长度限制，但也不要冗长跑题**——够把"怎么用、用在哪"讲透即可>。
```

要求：

1. **原文解释**必须忠实于原文语料，讲清论点本身；允许稍长，并把原文的**重点示例/重点说明**融入其中以保住原意（不改变含义、不铺陈与论点无关的枝节）。次要示例/数据可另用"例｜"一行引用。判据不变：示例不单独成为知识点，但可以作为论点解释的一部分被引用。
2. **费曼·换个领域**：每个知识点**只给一个最贴切的类比**（不要堆多个）。优先取自学习者熟悉的相邻领域（可借知识地图里的模型，也可用日常经验）。类比要让人"秒懂"，不是炫技。默认不写失效边界；**仅当这个类比容易把人带偏时**，补一句 `⚠边界：…`（一句话，别成段）。
3. **如何应用**：这是个人知识地图发力的地方。必须写清命中的地图 L3 模块（模块名 + 锚例），并给出**具体、可执行、可验证**的动作或提醒——落到学习者自己的生活/工作/投资场景。此处**以说清楚为准，不设硬长度限制，但也不要冗长**：需要几句把"怎么用"讲透就写几句。无对应模型时，给通用可执行动作，并在文末登记地图空白。
4. 主语言必须是简体中文。

### 文末（可选）：地图空白提示

若本章出现"无对应模型"的知识点，在文档末尾用一小节登记：`## 地图空白提示`，逐条列出"知识点 → 为何地图里无对应模型 → 建议（可作某萌芽区模型的转正锚例，或建议新建概念）"。无则整节省略。

> 不再包含：五阶段学习材料、记忆技术、学习顺序建议、测试与薄弱环节定位。这些一律不写。

## 执行要求

1. **预处理**：视频/音频先经 `video2text`（或 `bili-video-to-text`）转文字稿；读取语料统计正文字数（≤5000 中文字或 ≤2500 英文单词为短材料，超过为长材料）；完整读取个人知识地图建立可用模型清单。
2. **先做"前置：知识点划分"**：通读语料，产出知识点清单，明确区分论点与示例。这一步没做完，不得开始写卡片。
3. 按"询问规则"确认（长材料确认重点章）。
4. 按"卡片模板"逐点填写：先填"一、锚点总览"表，再逐个知识点写"二、知识点卡片"。
5. **锚点质量是本命令的生命线**：每个锚点必须 ≤20 字、punchy、可在实践中默念。若一个知识点憋不出好锚点，通常说明它不是独立知识点，应合并或删除。
6. **忠实性边界**：
   - 原材料的**论点、事实、数据、人名、引文**必须在语料中真实存在，禁止捏造。
   - **锚点、费曼类比、应用动作**属于本命令要求生成的教学性内容，允许创作，但必须与原文含义一致，且能区分"原文说了什么"与"为帮助学习而构造了什么"。
7. 完成后更新 `[libraryName]/learning/index.md`。

## 长材料处理（subagent 分章节）

1. 长材料（>5000 中文字或 >2500 英文单词）必须分章节处理，禁止单次整体压缩。
2. 主 AI 先完整浏览材料，按原文目录（无目录则按主题）切分章节并编号；每块过大时在对应 subagent 内部再拆子模块，但每章仍只产出一个 md。
3. 主 AI 先向用户复述章节清单和处理计划（每章交给哪个 subagent、产出哪个文件），再开始执行。
4. **每章一个 subagent**，各 subagent 先做"前置：知识点划分"，再按"卡片模板"产出该章的 `NN-[章节名].md`；subagent 之间不得跨章合并。
5. subagent 完成后，主 AI 逐一回收检查：知识点划分是否把示例误当知识点、锚点是否 ≤20 字且到位、每卡是否只有一个类比、"如何应用"是否真接到了知识地图、有无捏造。复核通过才算完成。
6. 主 AI 亲自编写 `00-总览.md`，内容为：
   - **全书锚点墙**：把各章所有锚点汇成一张表（章 → 知识点 → 锚点），这是全书最有价值的一页。
   - **结构图**：全书核心论点如何咬合（mermaid）。
   - **跨章模型命中矩阵**：各章命中的地图 L3 模型汇总（横向拓展索引）。
   - **地图空白提示汇总**：各章登记的空白 + 值得转正/建概念页的建议。
   - **各章文档目录**（链接）。
   - 不写全书级测试/学习顺序/薄弱环节。
7. 若"必须使用 subagent"与运行环境上层约束冲突，先显式说明冲突点并询问用户；冲突未澄清前不得擅自改为单 agent。

## 询问规则

1. 编译开始前，最多问 2 个问题（选择题）：
   - **学习目的**：A. 实践应用（默认，"如何应用"接知识图谱、给可执行动作） B. 兴趣理解（费曼类比讲透即可，应用从简）。默认 A。
   - **重点章**（仅长材料需要问）：列出章节清单让用户指定重点章；重点章可多提炼几个知识点、类比讲得更透，非重点章只留最核心的几张卡。默认全书均衡。
2. 用户未回复、拒绝回答或无法提供时，一律按默认值执行，不反复追问。

## 硬性约束

- 只允许写入 `[libraryName]/learning/` 下的文件；不得修改 `raw/`、`wiki/sources/` 下的已有文件，也不得修改个人知识地图（只读取材源）。
- **先划分知识点、区分论点与示例**：示例不单独成为知识点；重点示例可融入该卡"原文解释"以保住原意，次要示例作"例｜"引用；但禁止把案例/研究过程铺陈成段。这是本命令的第一约束。
- **每个知识点必须有一句 ≤20 字的锚点**；憋不出好锚点的条目应合并或删除，不允许留没有锚点的知识点。
- **每个知识点只给一个最贴切的类比**；默认不写失效边界，仅在类比会误导时补一句 `⚠边界`。
- **"如何应用"必须真正接到个人知识地图**（命中的 L3 模块名 + 锚例 + 一个可执行动作），不得写成空泛口号。
- 文档结构固定为"一、锚点总览 + 二、知识点卡片（+ 可选 地图空白提示）"；**不写五阶段材料、记忆技术、学习顺序、测试**。
- 原材料的论点/事实/数据/引文禁止捏造；教学性生成内容（锚点/类比/应用）必须与原文含义一致且可区分。
- 视频/音频必须先转文字，不得凭印象编写。
- 长材料必须分章节交给 subagent，主 AI 必须复核回收结果。
- 主语言必须是简体中文；不确定的内容标 `Confidence: Low`。
- 如果本规范与运行环境上层约束冲突，必须显式说明冲突点并询问用户如何处理。
