# atlas

## 基础要求

目的：

给定一个宽泛的领域，通过多类权威来源交叉验证，产出该领域的「知识地图」：这个领域由哪些知识模块构成、模块间的层级与先修关系、哪些是承重必学、哪些是选学或前沿，最终落成一份可逐项打勾的学习 checklist。

本命令解决的是「进入一个陌生领域时，不知道该学什么、先学什么」的问题，发生在 `learn`（学一份资料）和 `ingest`（收一份资料）之前。它的核心价值不是罗列知识点，而是**理清层级、依赖与主次**——凭感觉列出的清单几乎总是粒度混杂（如把「三大营养元素」与「饮食」并列、把「设计模式」与「计算机原理」并列），本命令必须把这种混杂拆开。

两条贯穿始终的核心原则：

1. **三角验证**：模块是否成立，取决于有几类独立来源支持它，而不是模型自己觉得它重要。模型自身知识只能用来起草假设，不计入证据。
2. **主次优先于完备**：地图不是百科全书。每个模块必须标注是否「承重」，让学习者知道哪 20% 撑起了领域的 80%。

命令格式：

- `atlas [可选:libraryName] [领域] [可选:深度]`

示例：

- `atlas 大语言模型`
- `atlas 健身 L3`
- `atlas fitnessWiki 健身`
- `atlas aiagentWiki AI Agent L1`

适用场景：

- 准备进入一个新领域，需要先拿到模块全景与学习路径
- 已有某领域的 library，想知道库内资料覆盖了地图的哪些部分、缺哪些（配合 libraryName 使用）
- 为某个领域规划该往 `raw/` 里收集什么资料

输入：

- 一个可选的 `libraryName`
- 一个领域名称（**必填**）
- 一个可选的深度：`L1` / `L2` / `L3`（也接受 `1` / `2` / `3`）

输入要求：

- **参数识别规则**：
	- 第一个参数若匹配 `*Wiki` 形式（以 `Wiki` 结尾），视为 `libraryName`；否则视为领域名称，本次不绑定 library。领域名称一定不会匹配 `*Wiki`。
	- 最后一个参数若匹配 `L1`/`L2`/`L3`/`1`/`2`/`3`，视为深度；否则视为领域名称的一部分（领域名称可含空格，如 `AI Agent`）。
- 若识别出的 `libraryName` 在仓库根目录下不存在对应目录，必须提示用户（笔误还是尚未建库），不得擅自新建 library，也不得静默当作无 library 处理。
- 缺少领域名称时，必须提示用户补充，否则不能进入后续步骤。
- 深度默认 `L2`：
	- `L1`：只产出大模块（5~12 个）
	- `L2`：大模块 + 子模块
	- `L3`：大模块 + 子模块 + 知识点
- 领域过宽（如「科学」「工程」）以致 L1 模块会超过 12 个、或各模块本身就是独立学科时，应先向用户建议收窄，或说明将按「学科群」做 L1 并建议对感兴趣的 L1 模块再单独执行 `atlas`。

输出结果：

- 知识地图文件：
	- 提供 `libraryName` 时：`[libraryName]/wiki/atlas/知识地图-[领域].md`
	- 未提供时：仓库根目录 `atlas/知识地图-[领域].md`
- 登记索引：
	- 提供 `libraryName` 时：更新 `[libraryName]/wiki/index.md` 的 `## 知识地图（atlas）` 区块
	- 未提供时：更新 `atlas/index.md`
- 终端输出摘要：模块总览表 + 推荐学习路径 +（若有 library）覆盖缺口摘要

## 执行要求

### 第一阶段·起草假设

1. 用模型自身知识为该领域起草一版 L1 模块假设清单，并同时列出「应该去查的权威来源」清单（具体到文档名、课程名、书名、综述名）。
2. 这一版只是待验证的假设，不得直接作为结果输出。

### 第二阶段·联网采证

3. 按以下来源类别联网采证，**至少覆盖其中 4 类**；某类在该领域确实不存在（如该领域没有认证考纲），在采证记录中写明「该类无」，不得硬凑：

| # | 来源类别 | 例子 | 主要用途 |
|---|---|---|---|
| ① | 权威知识体系 / 认证考纲 | SWEBOK、ACM/IEEE CS2023、NSCA-CSCS 考试大纲、CFA 大纲、PMBOK | 模块划分与层级（可信度最高） |
| ② | 大学培养方案 / 课程序列 | MIT OCW、Stanford 课程序列、国内专业培养方案 | 先修关系与学习顺序 |
| ③ | 经典教材目录（至少 2 本、尽量跨流派） | 领域公认教材的章节目录 | 共识模块（交集）与完整覆盖范围（并集） |
| ④ | 综述论文 / Handbook / 百科大纲页 | 领域综述、Wikipedia「Outline of X」、斯坦福哲学百科 | 模块结构；注意综述发表年份 |
| ⑤ | 学术分类体系 | ACM CCS、arXiv 分类、MeSH、MSC、中图分类法 | 领域边界与上下级关系 |
| ⑥ | 从业者路线图 | roadmap.sh、awesome-list、GitHub 课程仓库、岗位 JD、面试题库 | 实践中真正用到什么 |
| ⑦ | 前沿信号 | 顶会 track 名称、近一年综述 | 补充教材尚未收录的新模块 |

4. 每个被采用的来源都必须附可核验的 URL；查不到原文的大纲、目录不得凭记忆复述或编造。
5. 来源调研可按类别并行交给 subagent，但对照合并、分层、定稿必须由主 AI 完成。

### 第三阶段·对照合并与分层

6. **对齐模块**：把各来源的章节 / 模块映射到统一的模块名上；名称不同但内容相同的合并，粒度混杂的拆开到正确层级。
7. **证据计数**：每个模块记录支持它的**来源类别数**（同一类别的多个来源只算 1）。类别 ⑦ 前沿信号单独计。
	- 支持类别数 ≥2：可进入正式地图
	- 支持类别数 =1：移入 `## 待验证候选`，不进正式地图
	- 仅有模型假设、无任何外部来源支持：删除，不得出现在报告中
	- 仅由 ⑦ 支持的新方向：可进入正式地图，但必须标注为「前沿」层级
8. **分层**：按深度参数产出 L1 → L2 → L3。同一层内做 MECE 自检（不重叠、不遗漏）；L1 数量控制在 5~12 个，超出说明粒度过细或领域过宽。
9. **属性标注**，每个 L1 与 L2 模块必须标注：
	- 层级：`基础` / `核心` / `应用` / `前沿`
	- 主次：`承重` / `选学`。承重指不掌握就无法理解领域其余部分、或实践中绕不开的模块；承重模块不应超过总数的一半
	- 稳定性：`稳定` / `快变`
10. **先修关系**：梳理 L1 模块间的先修依赖，用 mermaid 画出有向图，并给出一条推荐学习路径（基础 → 承重核心 → 应用 / 选学 → 前沿）。
11. **领域边界**：写明该领域的一句话定义、明确不在范围内的相邻领域，以及与相邻领域的重叠地带。

### 第四阶段·对接个人知识地图（默认执行）

12. 完整读取个人知识地图 `/Users/aaron/workspace/个人/天赋/知识地图.md`，建立已内化的 L3 模型清单。
13. 逐个 L1 / L2 模块判断是否命中可迁移的 L3 模型：命中则标注模型名，提示「相邻领域共通处，可少学」；未命中不标注。
14. 铁律：宁可不标，也不牵强套用。若文件缺失，在元信息中标注 `知识地图: 未找到` 并跳过本阶段。

### 第五阶段·库内覆盖对照（仅在提供 libraryName 时执行）

15. 读取 `[libraryName]/wiki/index.md`、`[libraryName]/wiki/concepts/index.md`（若存在），必要时下钻 `wiki/sources/` 与 `wiki/concepts/` 的具体页面。
16. 为地图中的每个 L1 / L2 模块判定覆盖状态，并附库内页面链接作为依据：
	- `已覆盖`：有 sources 系统论述，或已有对应概念页
	- `部分覆盖`：只有零散提及
	- `未覆盖`：库内无相关内容
17. 对 `未覆盖` 与 `部分覆盖` 中的**承重**模块，给出建议补充的 raw 类型（书 / 论文 / 课程 / 视频等）及具体推荐（附 URL），按优先级排序。
18. 覆盖对照只做建议，不自动下载、不自动 ingest、不修改 `uningest.md`。

### 第六阶段·成文与留存

19. 报告结构固定如下（二级标题不含空格）：
	- 元信息：领域、library（无则写「无」）、深度、截至 yyyy-MM、`知识地图: 已读取 / 未找到`、`库内覆盖对照: 已执行 / 未执行`、Confidence
	- `## 领域定义与边界`
	- `## 模块总览`：L1 模块表（模块 / 一句话定义 / 层级 / 主次 / 稳定性 / 证据类别数 / 知识地图命中 /（有 library 时）覆盖状态）
	- `## 学习路径`：mermaid 先修关系图 + 推荐学习顺序
	- `## 知识清单`：按 L1 → L2（→ L3）展开的 checklist，格式见下
	- `## 库内覆盖对照`（仅有 library 时）：覆盖状态汇总 + 按优先级排序的补料建议
	- `## 待验证候选`：仅 1 类来源支持的模块，写明唯一来源
	- `## 采证记录`：按来源类别 ①~⑦ 列出实际查阅的来源与 URL；不存在的类别写「该类无」
	- `## 修订记录`
20. `## 知识清单` 中每个模块的格式：

```markdown
- [ ] **L1 模块名**｜核心·承重·稳定｜证据 4 类（①②③⑥）
	- 定义：一句话
	- 先修：模块名 / 无
	- 知识地图命中：〔L3 模型名〕（仅命中时写）
	- 覆盖：已覆盖（[页面](链接)）（仅有 library 时写）
	- 入门关键词：……
	- 代表资料：[资料名](URL)
	- [ ] L2 子模块名｜层级·主次·稳定性｜一句话定义
		- [ ] L3 知识点（仅深度 L3 时）
```

21. **同一领域再次执行时，就地更新原文件，而非新建**：
	- 必须保留用户已勾选的 `[x]` 状态；模块被重命名或合并时，把勾选状态迁移到新模块上
	- 被删除的模块移入 `## 修订记录` 并说明原因
	- 在 `## 修订记录` 追加一行：日期、深度、主要变更
22. 完成后登记索引：
	- 有 library：在 `[libraryName]/wiki/index.md` 中维护 `## 知识地图（atlas）` 区块（不存在则新建，放在 `## 前沿与争论（fragment）` 之后，若无该区块则放在 `## 概念索引` 之后），每个领域一行：`- [知识地图-领域](atlas/知识地图-领域.md)（截至 yyyy-MM · 深度 · 一句话摘要 ≤100 字）`
	- 无 library：在 `atlas/index.md` 中按同样格式维护一行（文件不存在则新建，标题为 `# atlas 知识地图索引`）

## 硬性约束

- 模块必须有外部来源支撑：正式地图中的每个模块至少有 2 类来源支持（前沿层级除外）；模型自身知识不计入证据。
- 所有外部来源必须附可核验的 URL；不得编造书名、课程名、大纲内容或链接。
- 地图的分层与证据判断若存在明显的主观综合成分（如领域边界本身有争议、各来源划分差异大），必须标注 `Confidence: Low` 并说明原因。
- 落盘范围仅限：知识地图文件本身，以及对应索引（`[libraryName]/wiki/index.md` 的 atlas 区块或 `atlas/index.md`）。严禁修改 `wiki/sources/`、`wiki/concepts/`、`concepts/index.md`、`uningest.md` 及个人知识地图。
- 禁止执行复制、剪切、移动或重命名 raw 文件的操作。
- 补料建议只做 proposal，不自动下载、不自动 ingest。
- 报告主语言必须是简体中文；专有名词、来源原名可保留原文。

## 与其他命令的关系

- 下游 `ingest` / `check_uningest`：`## 库内覆盖对照` 的补料建议是收集 raw 的待办清单。
- 下游 `learn`：拿到补料后，按学习路径逐份 `learn`。
- 下游 `five-books-field-primer` skill：可对某个承重 L1 模块单独挑五本书。
- 下游 `concept`：知识清单中的模块名可作为概念命名的参考，但 atlas 不直接创建概念页。
- 旁路 `frontier`：地图中标为「前沿」的模块，可在建库后用 `frontier` 做争论与前沿的深入盘点。
- `query` 不以 atlas 文件作为知识来源：atlas 是导航地图，不是编译后的知识。
